## UTC decision

The proposed blanket exemption for locals named `*Utc` is rejected. The auth locals feed `GetRefreshExpiry(nowUtc)`, `CanUse(nowUtc)` and expiry comparisons, not exclusively parameters named `*AtUtc`. The analyzer now recognizes a direct `*AtUtc` argument, including expiry arithmetic, and a local only when every reference is a timestamp argument or timestamp field/property assignment. It still diagnoses calendar extraction, extra non-timestamp uses, reassignment and unused locals. This removes five proven false positives. No user-facing calendar date was reclassified, and no timestamp or response contract changes.

The scheduler exemptions are prefetch boundaries, not the send date or dedupe day. Both proactive check-ins and slip alerts resolve their final date from the user's converted clock. The accounting-day exemptions select UTC operator cost reports. Retention cutoffs expire internal rows by age. The retained Report backing field remains configured in the persistence model after the social runtime removal; deleting it would change persisted schema beyond this audit.

The MediatR wrapper source is pinned to the repository commit in the installed package's nuspec. It substitutes the request token when its optional continuation token is default. The strengthened validation tests assert explicit token forwarding and run the real installed wrapper with and without validators; the handler token and response stay the same.

## Behavior and verification

The catalog's capabilities, operations, surfaces and user-data catalog serialize identically before and after the refactor. The SHA-256 of both serialized snapshots is `29a8ad02be0eebdb51a2108f1c6e96069f00c88972cd2175da6895a26fb60062`. The forwarding factory is replaced by the same record constructor; repeated schema arrays and literals are reused without changing their values.

The unchanged analyzer suite passed 32 tests and the unchanged checker passed 38. Added timestamp-sink cases failed twice before narrowing and pass afterwards. The duplicate-reason case failed because the original checker incorrectly accepted the duplicate. The unchanged controller/service/auth/catalog selection passed 678 tests before the library changes. The new support-controller case failed with two user-claim reads while logging was disabled; enabled and disabled logging preserve the same response after the guard. The unchanged validation tests passed four cases; the strengthened direct continuation cases failed twice before forwarding the token, while both real-wrapper parity cases already passed.

A broader optional `latest-all` probe also enables diagnostics outside this ticket and in generated migrations. Those unrelated diagnostics are outside the closed suppression audit. Verification scopes CA1859, CA1861 and CA1873 to changed source files and keeps the normal repository build as the delivery gate.
